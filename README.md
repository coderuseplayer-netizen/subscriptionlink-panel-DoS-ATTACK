## 🧠 این ابزار چیست؟

این ابزار یک **چهارچوب تست استرس لایه ۷ چند‌برداری و تطبیقی** است که به طور خاص برای ارزیابی مقاومت پنل‌های لینک اشتراک (مانند V2Ray، Clash، Sing-box) که فایل‌های کانفیگ را از طریق URL تحویل می‌دهند، طراحی شده است. این ابزار با شبیه‌سازی هزاران درخواست همزمان از طرف کلاینت‌ها، نحوه عملکرد سرور را تحت بار بالا، رقابت دیتابیس، دور زدن کش، و اشباع ظرفیت اتصالات بررسی می‌کند.

این ابزار از **asyncio** و **aiohttp** برای ایجاد هزاران اتصال HTTP همزمان با کمترین سربار استفاده می‌کند و شامل یک **کنترل‌کننده همزمانی تطبیقی** است که تعداد workerهای فعال را بر اساس رفتار لحظه‌ای هدف (بلاک شدن، محدودیت نرخ، خطاهای سرور و...) به صورت پویا تنظیم می‌کند.

> ⚠️ **هشدار قانونی**  
> این ابزار **فقط** برای تست سرورهای خودتان یا سیستم‌هایی که اجازه کتبی صریح دارید مجاز است. استفاده غیرمجاز علیه سرویس‌های شخص ثالث غیرقانونی است و ممکن است عواقب شدیدی داشته باشد. نویسنده هیچ مسئولیتی در قبال سوء استفاده ندارد.

### 🧬 کنترل‌کننده همزمانی تطبیقی

- با تعداد worker اولیه تعیین‌شده توسط کاربر شروع می‌شود (پیش‌فرض 200).
- هر 20 ثانیه آمار پاسخ‌ها را تحلیل می‌کند:
  - **403 یا 429 زیاد** → کاهش workerها برای جلوگیری از بن شدن IP.
  - **5xx یا تایم‌اوت زیاد** → افزایش workerها برای فشار بیشتر.
  - **نرخ موفقیت بالا** → افزایش workerها برای حداکثر throughput.
- به صورت خودکار workerها را spawn یا cancel می‌کند بدون توقف حمله.
- سقف workerها از قبل تعیین شده (1000 برای حالت ۱، 800 برای حالت‌های ۲ و ۳).

### 📊 لاگ لحظه‌ای و گزارش JSON

- خروجی ترمینال با کدهای رنگی برای تشخیص سریع وضعیت.
- هر رویداد با زمان ثبت می‌شود.
- بعد از هر حمله، گزارش دقیق JSON ذخیره می‌شود شامل:
  - تعداد کل درخواست‌ها، نرخ موفقیت، RPS (درخواست بر ثانیه)
  - تعداد بلاک 403، محدودیت 429، خطاهای سرور 5xx، تایم‌اوت‌ها
  - تعداد قفل‌های دیتابیس (حالت ۲)
  - درصد دور زدن کش (حالت ۳)
  - تعداد نهایی workerها

### 🎯 تخصصی برای پنل‌های اشتراک

- استفاده از `User-Agent`های واقعی کلاینت‌های محبوب VPN (v2rayN، Clash، Shadowrocket، sing-box و...).
- ارسال هدرهایی که رفتار کلاینت واقعی را تقلید می‌کنند (`Accept`, `Connection`, `Cache-Control`).

## 📈 تفسیر لاگ‌ها

لاگ‌ها با کدهای رنگی مشخص می‌شوند:

| رنگ / برچسب | معنی |
|----------------|---------|
| 🟢 `[200 OK]` | درخواست موفق – هدف به طور عادی پاسخ می‌دهد. |
| 🔴 `[BLOCKED/BAN]` (403) | IP یا الگوی درخواست شما توسط هدف (WAF، Cloudflare و...) بلاک شده است. |
| 🟡 `[RATE-LIMIT]` (429) | هدف درخواست‌ها را throttling می‌کند – نشان می‌دهد محافظت فعال است. |
| 🔴 `[SRV-ERR 5xx]` | خطای سرور – معمولاً نشانه خوبی است؛ هدف ممکن است تحت فشار باشد. |
| ⏰ `[DEADLOCK/TO]` | تایم‌اوت درخواست – احتمالاً سرور بیش از حد بارگذاری شده یا اتصالات اشباع شده است. |
| 🟣 `[DB-LOCKED!]` | قفل یا رقابت دیتابیس تشخیص داده شد (فقط حالت ۲). |
| 🟡 `[QUEUE-DELAY]` | تأخیر بالا (>2500 میلی‌ثانیه) – دیتابیس ممکن است در حال تقلا باشد. |
| 🔵 `[CONN-HOLD]` | حمله اتصال آهسته که یک اسلات ورکر را نگه می‌دارد (حالت ۳). |
| 🟠 `[BYPASS-HIT]` | کش دور زده شد – ضربه مستقیم به سرور اصلی (حالت ۳). |

هنگامی که تعداد زیادی خطای `5xx`، تایم‌اوت و به ویژه `521`، `522` یا `523` مشاهده می‌کنید، سرور اصلی به احتمال زیاد تحت فشار شدید است و ممکن است در حال crash شدن یا غیرقابل دسترس شدن باشد.

## 🌍 پشت Cloudflare / CDN – چه انتظاری داشته باشیم؟

Cloudflare و CDNهای مشابه به عنوان سپر بین ترافیک شما و سرور اصلی عمل می‌کنند. این ابزار به طور غیرمستقیم سرور اصلی را هدف قرار می‌دهد و با ارسال درخواست‌هایی که ممکن است کش CDN را دور بزنند یا از طریق CDN سرور اصلی را overload کنند، عمل می‌کند.

### کدهای خطایی که ممکن است ببینید:

| کد | معنی |
|------|---------|
| **520** | وب سرور خطای ناشناخته‌ای برگرداند (سرور اصلی crash یا misconfigured شده). |
| **521** | وب سرور down است – سرور اصلی اتصال را رد کرد. |
| **522** | تایم‌اوت اتصال – سرور اصلی خیلی دیر پاسخ داد. |
| **523** | سرور اصلی غیرقابل دسترس است – مشکل مسیر شبکه یا فایروال. |
| **524** | تایم‌اوت رخ داد – سرور اصلی بیش از 100 ثانیه برای پردازش زمان برد. |
| **525** | SSL handshake شکست خورد – معمولاً به دلیل بار بالای CPU. |
| **526** | گواهی SSL نامعتبر – ممکن است مربوط به overload باشد. |

این خطاها نشانه قوی از تأثیر حمله شما بر سرور اصلی پشت CDN هستند.

> **💡 نکته:** اگر تعداد زیادی پاسخ `403` یا `429` دریافت می‌کنید، CDN در حال بلاک کردن شماست. در این صورت ممکن است لازم باشد ترافیک خود را از طریق پروکسی توزیع کنید یا همزمانی را کاهش دهید تا از بن شدن IP جلوگیری کنید. با این حال، گاهی اوقات نرخ بالای پایدار می‌تواند سرور اصلی را حتی اگر CDN برخی درخواست‌ها را بلاک کند، خسته کند.

## 🔍 تست با Check-Host

بعد از اجرای حمله برای چند دقیقه، می‌توانید وضعیت هدف را با استفاده از ابزارهای آنلاین مانند **Check-Host** بررسی کنید:

1. به [check-host.net](https://check-host.net/) بروید.
2. گزینه **HTTP** را انتخاب کنید.
3. URL کامل هدف را وارد کنید (مثلاً `https://example.com/sub/abc123`).
4. چندین لوکیشن (جهانی) را برای دید وسیع‌تر انتخاب کنید.
5. روی **Check** کلیک کنید.

اگر هدف down یا به شدت تخریب شده باشد، خواهید دید:
- زمان پاسخ بالا
- تایم‌اوت از بسیاری از لوکیشن‌ها
- خطاهای HTTP 5xx یا 403/429 از مناطق مختلف
- احتمالاً "Connection refused" یا "Host unreachable"

این یک روش عالی برای تأیید تأثیر تست استرس شماست.

## 🛡️ ردیابی IP و بن شدن

بسیاری از اهداف (به ویژه آنهایی که پشت Cloudflare هستند) از سیستم‌های اعتبارسنجی IP استفاده می‌کنند و ممکن است پس از تشخیص رفتار مخرب، IP شما را بن کنند.

- **نحوه کار:** آن‌ها نرخ درخواست، یکنواختی user-agent و الگوها را بررسی می‌کنند. اگر IP شما هزاران درخواست در زمان کوتاه بفرستد، flag شده و موقتاً یا دائماً بن می‌شود.
- **چه اتفاقی می‌افتد:** ممکن است پاسخ‌های `403 Forbidden` یا `429 Too Many Requests` دریافت کنید. گاهی اتصال به سادگی قطع می‌شود.
- **راهکار:**
  - از VPN یا پروکسی برای تغییر IP استفاده کنید.
  - همزمانی را کاهش دهید تا زیر رادار بمانید.
  - user-agent ها را بچرخانید (ابزار این کار را خودکار انجام می‌دهد).
  - برای تست جدی، استفاده از زیرساخت توزیع‌شده یا بات‌نت را در نظر بگیرید.

> **توجه:** کنترل‌کننده تطبیقی سعی می‌کند وقتی نرخ بلاک بالا را تشخیص دهد، همزمانی را کاهش دهد، اما اگر هدف به شدت بن می‌کند، ممکن است همچنان بلاک شوید.

## 🐞 باگ‌های شناخته‌شده و محدودیت‌ها

- **اتمام فایل دیسکریپتور:** اگر تعداد workerها را خیلی بالا ببرید (مثلاً >2000)، ممکن است سیستم با خطای `Too many open files` مواجه شود. نصب‌کننده محدودیت را به 10000 افزایش می‌دهد، اما در صورت نیاز تعداد workerها را کاهش دهید.
- **سازگاری با ویندوز:** اسکریپت از `ulimit` استفاده می‌کند که در ویندوز موجود نیست. در ویندوز باید محدودیت‌ها را دستی تنظیم کنید یا از WSL استفاده کنید.
- **پشتیبانی پروکسی:** نسخه فعلی **چرخش پروکسی داخلی** ندارد. برای دور زدن بن IP باید پروکسی‌ها را به صورت دستی ادغام کنید.
- **پایداری کنترل‌کننده تطبیقی:** در موارد نادر، spawn/cancel سریع taskها ممکن است race condition ایجاد کند. اگر بی‌ثباتی مشاهده کردید، همزمانی را ثابت نگه دارید (گزینه غیرفعال کردن auto-adjust هنوز پیاده‌سازی نشده).
- **غیرفعال بودن تأیید SSL:** برای سرعت، تأیید SSL خاموش است. این برای تست خوب است اما ممکن است هشدار گواهی نمایش دهد.
